# P2.1 — C shim skeleton + cgo build integration

**Branch:** main (Phase 2 is serial — see PARALLEL-WORK.md)   **Phase:** 2   **Depends on:** P1.0

## Goal

`internal/platform/darwin` becomes a real cgo package: one C shim that compiles, links and ships inside
the universal `.app`. This task lays down the conventions every later Phase 2/3 task follows — status
codes, error mapping, bitmap ownership, main-queue marshalling — so that P2.2 through P3.4 add functions
to an existing shim rather than each inventing a shape. It queries nothing and switches nothing.

## Files you may touch

- `internal/platform/darwin/` (shim.h, shim.m, shim.go, doc.go)
- `cmd/gotab/main.go` — must import the package, or the shim is never linked into the app
- `scripts/build.sh` — cgo changes what a universal build needs
- `docs/ROADMAP.md`, `docs/DECISIONS.md`

## What has to be answered

1. **Does the universal build survive cgo?** `build.sh` cross-compiles amd64 on an arm64 host. With no
   cgo in the tree that was free; with an ObjC shim it needs the target arch passed to clang as well as
   to Go. This is the task's real risk and the reason it comes first.
2. **Does `scripts/check.sh` stay green** — specifically, does the purity gate still prove `internal/core`
   reaches neither cgo nor `internal/platform` once a real cgo package exists for it to reach?
3. **What is the error convention across the boundary?** C cannot return a Go error. Fixed once here.

## Notes

**`CGMainDisplayID()` must be called before any other CoreGraphics use** in a process that is not a
regular AppKit app — D12 found CoreGraphics `abort()`s the process on first capture otherwise. It belongs
in the shim's one-time init, not in P2.6 where the abort would actually fire.

**No ARC.** cgo does not pass `-fobjc-arc` and every spike that works (`panel`, `sck`, `hotkey`) is
manual retain/release. Consistency with proven code beats a half-ARC shim.

Bitmap ownership is `ARCHITECTURE.md#the-memory-rule` and is not restated here.
