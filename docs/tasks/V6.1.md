# V6.1 — hotkey delivery latency, real keypress

**Phase:** 6   **Needs:** a human at the machine, Accessibility granted to the responsible process.
**Discharges:** the `assumption` at P0.2 / P3.5 — "the hotkey arrives inside 5 ms".

## Goal

Put a number on event → callback latency for a **real** ⌥⇥, against the < 5 ms budget the summon
path is designed around. TCC blocks synthesising the keypress (a synthetic event's timestamp is
stamped by the poster, not by the HID path — D15), so this cannot run unattended; that is why it
was deferred here rather than measured in P0.2.

## Prerequisites

- A Mac with a keyboard. No second display or Space needed.
- **Accessibility granted to the terminal** you run from — not to the built binary. Under `go run`
  the responsible process is the terminal (PLATFORM-LESSONS §5); an ungranted tap installs fine and
  then never fires, which looks identical to a broken hotkey. `spike/hotkey` checks
  `AXIsProcessTrusted` up front and says so.

## Protocol

```bash
go run ./spike/hotkey -manual -n 20
```

Then press ⌥⇥ twenty times at a normal cadence. ⌥⇥ is swallowed while the spike runs, so nothing
underneath sees it. The spike prints, per press, `CGEventGetTimestamp` → callback delta, and
separately:

- **the first C→Go crossing** (the tap callback arrives on a CoreFoundation thread the Go runtime
  has never seen; attaching one is a one-time cost the user never pays twice — D1 measured 39 ns for
  a crossing on a thread the runtime already owns, this is the other kind), and
- **steady-state** crossings (presses 2…20), with a two-clock-read baseline subtracted.

If the spike prints `INCONCLUSIVE` it did not get real HID-path events — check the grant.

## Acceptance

- [ ] Worst-case steady-state event → callback over 20 real presses is **< 5 ms**.
- [ ] The first crossing is reported as its own number, not folded into the average.
- [ ] `kCGEventTapDisabledByTimeout` did not fire during the run (a stalled callback disables the
      tap; the spike re-enables it, but a run where it tripped is not a clean measurement).
- [ ] Number + the first-crossing figure appended to `docs/DECISIONS.md`; `docs/ROADMAP.md` Phase 6
      row → ✅ with the number, P0.2's box → `[x]`, and the P0.2 / P3.5 `assumption` tags marked
      discharged.

## If it comes back over budget

This changes Phase 3 code, not just the roadmap. The tap already sits at the head of the session
event queue on its own thread (`hotkey.m`); if that is not enough the options are a lower-level
event source or accepting a larger summon budget — either is a design decision for
`docs/DECISIONS.md`, not a quiet fix.
