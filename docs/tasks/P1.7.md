# P1.7 — Thumbnail cache policy

**Branch:** feat/P1.7   **Phase:** 1   **Depends on:** P1.0

## Goal
A bounded LRU that decides **what to evict**. No bitmaps, no cgo — pure policy.

## Files you may touch
- `internal/core/cache.go`
- `internal/core/cache_test.go`

## Signatures (exact)
```go
func NewCache(capacity int) *Cache
func (c *Cache) Len() int
func (c *Cache) Contains(k CacheKey) bool
func (c *Cache) Touch(k CacheKey) (evicted []CacheKey)
func (c *Cache) Evict(k CacheKey) bool
func (c *Cache) Reset() (evicted []CacheKey)
```

## Behaviour that is not obvious
- **This package never holds a bitmap.** `Touch` returns the keys the caller must release; the
  platform layer does the releasing (ARCHITECTURE.md#the-memory-rule). Returning a key the caller
  then fails to release is a leak, so `Touch` must return **every** key it drops, exactly once.
- The returned slice is `c.evicted[:0]` reused across calls — the caller must consume it before the
  next `Touch`. Say so in the doc comment; this is the kind of aliasing that bites later.
- `Size` is part of `CacheKey` on purpose: the same window at a different tile size is a different
  entry. Serving a stale size is a visible bug.
- The bound exists for predictable peak footprint and a warm cache on summon, **not** to win a memory
  comparison — macOS already evicts idle bitmap pages (D9, D10). Do not justify it otherwise.
- `Capacity <= 0` must be rejected by `NewCache` (panic with a clear message): an unbounded cache is
  the exact failure this task exists to prevent.
