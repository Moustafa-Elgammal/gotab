# P4.4 — Multi-monitor & Spaces

**Phase:** 4  **Depends on:** P1.2/P1.3 (Order, Filter), P2.4 (Spaces), P3.1/P3.2 (panel, layout),
P4.1/P4.2 (the filter prefs)
**Owns:** `core.Order.RebuildFrom` + `sortByFocus` in `internal/core/order.go`; `Loop.Rules` and the
filter in `internal/app/loop.go`; `gt_active_screen` / `ActiveScreen` in `panel.{h,m,go}`;
`Enumerator.fillSpaces` in `window.go`; the wiring in `cmd/gotab`

## Goal

Two things the switcher has had the pieces for but never connected:

1. **The filter is live.** `core.Rules` — the settings-window checkboxes from P4.2 — now decides which
   windows the switcher shows. `internal/app`'s loop has ordered *every* window since P2.7.
2. **The panel follows the display.** `core.Layout` is sized for the screen under the mouse (its real
   visible frame and backing scale), not a guessed `Scale: 2`. Placement was already per-display
   (P3.1); now sizing is too.

## Contract

- `core.Order.RebuildFrom(m, rows)` — rebuild the presentation order over a caller-chosen row subset
  (the filter's output), sorted by `FocusSeq`. `Rebuild` and it now share `sortByFocus`.
- `Loop.Rules core.Rules` — set before `Run`; the zero value shows every switchable window on the
  current Space. `doRescan` refreshes `Rules.CurrentSpace` from `darwin.CurrentSpace()` each pass and
  rebuilds the order through `core.Filter` → `RebuildFrom` every pass.
- `darwin.ActiveScreen() (wPt, hPt, scale int)` — the display `gt_panel_show` will use, via the same
  `screen_under_mouse()` helper.
- `Enumerator.Enumerate` fills `core.Window.Space` for every returned window, in one extra crossing;
  0 (SkyLight unavailable / unmapped window) means "don't filter by Space".

## Acceptance

- [x] `internal/app`'s loop filters: a window that fails `Rules.Allows` is not in `Order`, so the
      renderer never shows it and cycling skips it. `-switch` gets `Rules` from prefs; `-watch` sets
      `ShowMinimized/Hidden/OtherSpace` true so it stays a raw view
- [x] `core.Window.Space` is populated by the enumeration; `Rules.CurrentSpace` is refreshed each
      rescan; the `ShowOtherSpace` rule has real values to compare (0-on-either-side still means

- [x] `core.Layout` is handed the real display: `panelRenderer.onState` sets `Screen` and `Scale`
      from `ActiveScreen()`, retiring the hard-coded `Scale: 2` (P4.1's V6.8 assumption)
- [x] `RebuildFrom` sorts by `FocusSeq` only, so a pass where nothing filter-relevant changed yields
      the identical order — `-watch`'s "print on change" stays quiet, which was P2.7's MRU check
- [x] `./scripts/check.sh` green (the `order.go` refactor keeps `internal/core`'s suite green);
      `scripts/build.sh` universal app builds; `-list -raw` and `-watch` degrade cleanly with no grant

## Findings

- **Rebuild every rescan, not "only when membership changed".** The old gate missed a window
  minimizing or the Space flipping — filter *inputs* that change without the window set changing. The
  order must follow those, and it is safe to: `RebuildFrom` sorts by `FocusSeq`, which a title or
  frame change never touches (`doRescan` upserts zero `FocusSeq` = "preserve", D22), so a no-op pass
  produces byte-identical `Order.Rows`. The cost is one `Filter` sweep plus one insertion sort over
  tens of rows, a few times a second at most.
- **`CurrentSpace` is runtime state, not a setting.** `Prefs.Rules()` leaves it 0; `doRescan` fills
  it from `darwin.CurrentSpace()` each pass — one cheap SkyLight call. A Space switch does not always
  raise an AX notification, but it changes which windows are on-screen, which does, so a rescan
  follows it in practice.
- **`ActiveScreen()` reads `NSScreen` off the loop goroutine.** AppKit documents `+[NSScreen screens]`
  as main-thread-only; in practice it and each screen's frame/scale are immutable snapshots refreshed
  on a notification, and reading them off-main is common. Marked an assumption in `panel.go` — V6.2 /
  V6.5 drive the real app and would surface a fault.
- **One extra crossing per enumeration for Spaces.** `fillSpaces` calls `SpacesOf` (P2.4: 1.4–4.8 ms
  for 54–63 windows). Enumeration is not the summon path (D5), so this is affordable; if it ever
  matters it can be gated on `!Rules.ShowOtherSpace`.

### Still not wired

- **`ActiveAppOnly`.** `Prefs.Rules()` sets the bool but not `Rules.ActiveApp`, and
  `core.Rules.Allows` is inert while `ActiveApp == 0`. It needs the frontmost application's pid
  captured on `Summon` (a `darwin.FrontmostApp()` and a field on the loop) — a small follow-up, not
  P4.4.
- **The panel *across* Spaces.** Its `collectionBehavior` (canJoinAllSpaces, fullScreenAuxiliary) is
  P3.1's, still a Phase-3 `assumption` → V6.2. P4.4 is about which *windows* are shown, not the panel
  itself.

## Notes
