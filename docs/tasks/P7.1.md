# P7.1 — Raise falls back to the application

**Phase:** 7  **Depends on:** P2.5 (the raise path), D46 (the gap)  **Owns:** `action.h`, `action.m`, `action.go`

## Goal

V6.5 (D46) drove the assembled switcher and found the gap the P2.3c join (D21) always implied: the
join surfaces windows Accessibility cannot enumerate — usually on another Space — so the panel shows
them, but `gt_window_raise` resolves a window through `kAXWindowsAttribute`, which does not list
them, so selecting one returns `ErrNoWindow` and nothing happens. In one `-switch` session, 12 of 12
selections onto `cg`-only tiles failed this way.

Make the switch land anyway: when the window will not resolve to an `AXUIElement` **and its owning
process is alive**, activate the *application*. The specific window is not reordered, but the app the
user was reaching for comes forward — the visible half of the switch. `Loop.Activate` already treats
a nil error as "switched".

## Contract

`Raise`'s Go signature is unchanged. The behaviour change is entirely inside `gt_window_raise`:

- When `copy_window_element` returns no element with status `GT_ERR_NO_WINDOW` **and** the owning pid
  (from `pid_for_window`, handed back through `*out_pid` even on the empty return) belongs to a
  running application, call `activate_app(pid)` and return `GT_OK`.
- `GT_ERR_NO_WINDOW` is still returned when the owning process is gone as well — the signal for P7.2
  to prune the window from the model.
- `GT_ERR_TIMEOUT` / `GT_ERR_NOT_TRUSTED` are **not** rerouted: an app that will not answer AX at
  all, or a revoked grant, is a different answer and is returned as-is. Only `GT_ERR_NO_WINDOW` — the
  clean "AX cannot see this window here" — takes the fallback.
- `Minimize` / `Unminimize` / `Close` are unchanged: there is no application-level equivalent of those
  gestures, so an unresolvable window is still `ErrNoWindow` for them.

Design notes taken while writing it:

- **`copy_window_element` now sets `*out_pid = owner` up front**, before it knows whether an element
  will be found. The three other callers ignore `pid` on an empty return, so this is free to them; it
  is what gives `gt_window_raise` a pid to activate when there is no element. A hit on the
  all-applications scan still overwrites it with the pid that actually answered.
- **`app_is_alive(pid)` uses `runningApplicationWithProcessIdentifier:`**, not `kill(pid, 0)`. The
  question is not "is this pid alive" but "is it something `activate_app` could bring forward" —
  `NSRunningApplication` returns nil for a terminated process and for a pid that was never a GUI app,
  which is exactly the line between the fallback and `ErrNoWindow`.
- **The fallback is gated on `st == GT_ERR_NO_WINDOW` specifically.** A wedged app (`GT_ERR_TIMEOUT`)
  has a live pid too, but its failure is "not answering AX", not "AX cannot see this window on this
  Space", and the existing `ErrTimeout` sentinel is a contract callers may already lean on.
- P7.3 (optional) would make a real Space switch so this app-only fallback becomes the exception
  rather than the rule for other-Space windows. P7.1 is the floor; P7.3 is a private-API bet.
