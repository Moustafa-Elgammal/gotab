# V6.10 — VoiceOver heard, not just written

**Phase:** 6   **Needs:** a human at the machine with VoiceOver (or Accessibility Inspector).
**Discharges:** the P5.2 `assumption` — the accessibility tree is written against the AppKit API and
has never been heard by a screen reader (an agent host has none — D41).

## Goal

Drive `gotab -switch` and `gotab -settings` with VoiceOver on and confirm the switcher is actually
usable without sight: every tile announced, the selection spoken on **every** cycle, the panel a
labelled container, and every settings control labelled.

## Prerequisites

- `build/GoTab.app`, Accessibility granted.
- VoiceOver (⌘F5). Accessibility Inspector (from Xcode) is an acceptable substitute for the element
  tree but cannot verify the *announcements* — use VoiceOver for those.

## Protocol — switcher

1. VoiceOver on. `gotab -switch`. Summon.
2. The panel reads as a container labelled **"Window switcher"** (group role).
3. Each tile is announced as **"&lt;title&gt;, &lt;app&gt;"**, button role.
4. Hold ⌥, press ⇥ repeatedly. On **every** cycle the newly selected tile is spoken (a high-priority
   announcement + a selection-changed notification — `panel_populate`, D41). Not just the first move;
   every one.
5. The tile frame VoiceOver highlights matches the visible tile (flipped-space frame is right).
6. **VoiceOver press on a tile raises that window and dismisses the panel (D59)** — the same end
   state as releasing ⌥. Navigate the VO cursor to a non-selected tile, press (VO-Space), and
   confirm that window comes forward and the panel closes. (Before D59 this was a deliberate no-op;
   it no longer is.)

## Protocol — settings

`gotab -settings` with VoiceOver on. Every control has a spoken label:

## If the selection is silent on later cycles

`g_a11y_last_*` debounces the announcement (D41); a bug there would speak the first move and go quiet.
That is a `panel.m` fix, back to P5.2 — with a note of exactly which cycle went silent.

## Findings — agent, structural half only (2026-09-08, D51)

`gotab -switch -demo` (new flag: skips the hotkey, scripts a summon that holds and cycles) puts the
panel up offscreen; its accessibility tree was walked with System Events (the Accessibility-Inspector
substitute this contract allows). No VoiceOver — announcements were not heard.

**Confirmed:**

- [x] Each tile is `AXButton` role (`GTTileElement.accessibilityRole`).
- [x] Each tile's accessible label is **"&lt;title&gt;, &lt;app&gt;"** — live: `"Facebook - Google
      Chrome - Moustafa, Google Chrome"`, `"gotab, GoLand"`, `"New Message, Mail"`. Matches
      `a11y_label()`.
- [x] Exactly one tile carries `AXSelected = true`, and it **advances on every cycle** — sampled
      across three consecutive demo cycles, Chrome → GoLand → Mail, each with the right label. This
      is the structural half of "selection spoken on every cycle"; the *speech* still needs ears.
- [x] Tile press is a no-op (`GTTileElement.accessibilityPerformPress` returns `NO`) — V6.10 §6, in
      code.

**Concern for the VoiceOver run:** the `"Window switcher"` label lives on `GTTileView`, which
returns `isAccessibilityElement = NO`. Live, the tile buttons appear as **direct children of the
panel window**, the window's `AXTitle` is **empty**, and its subrole is `AXSystemDialog` — there is
no element in the tree carrying the text "Window switcher". VoiceOver may still voice the group via
the parent chain, or it may land the user on an unlabelled system dialog. **If it is silent, that is
a P5.2 fix** — put the label on the window/panel, or make the container a real accessibility
element.

**Not done:** the settings-window control labels (`entire contents` via System Events hangs on that
window — needs Accessibility Inspector or VoiceOver), and every spoken announcement.

**Status:** V6.10 is **partial** — per-tile a11y verified structurally; the container label, the
settings labels, and all announcements need a human with VoiceOver.

## Follow-up — the two concerns above are now addressed in code (2026-09-08)

- **Container label (D58).** The D51 "concern" is fixed. `"Window switcher"` no longer relies on
  `GTTileView` (AppKit was promoting the synthetic tile elements past that non-element view): it is
  set as the panel window's `AXTitle` in `gt_panel_create`, and `g_effect` is pinned as a
  non-element pass-through. The per-cycle announcement also now carries the position —
  `"<title>, <app>, N of M"` (`a11y_spoken()`) — so a no-sight user always knows their place even if
  the container tree still does not resolve. **Human check:** the label is actually *heard* on
  summon, and the position on every cycle.
- **Press-to-raise (D59).** The "Tile press is a no-op" line above no longer holds. A VoiceOver
  press on a tile now fires `goPanelChooseTile` → a `Choose` event that selects that tile and
  activates. §6 above is updated: confirm a VO press switches to that window and dismisses.
- **Still code-only, needs ears:** every spoken announcement, the settings-window control labels
  (they are set in `settings.m` — P5.2 — but never heard), and the press-to-raise round trip.
