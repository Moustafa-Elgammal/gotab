# V6.4 — thumbnail memory at realistic scale

**Phase:** 6   **Needs:** a real Mac, Screen Recording granted, ~50 windows open across several apps,
a Retina display.
**Discharges:** the P2.6 / P3.3 `assumption`s — a 50-window Retina cache staying inside a sane bound
(D14 saw 8.3 MB for 20 tiles at 400 px — that is a shape, not the number), and the 2 s capture
timeout being headroom rather than a measured tail.

## Goal

Confirm the bounded LRU (P1.7 policy, `ThumbnailCacheSize` default 64) keeps peak thumbnail memory
inside a stated number when the switcher is driven against ~50 real windows at the display's real
backing scale — measured on `spike/procmem`'s **`IOSurface`** row (SCK output is IOSurface-backed
and invisible to process footprint — D12), sampled **at summon** because the resident figure decays
within seconds (D8).

## Prerequisites

- `build/GoTab.app` running, Screen Recording granted.
- ~50 windows across ≥ 5 apps so the prefetcher has a full working set.
- `ThumbnailCacheSize` at its default (64) for the headline run; repeat at a smaller bound to show
  the policy actually clamps.

## Protocol

```bash
# in one terminal, sampling the running bundle:
go run ./spike/procmem -name GoTab -n 20 -every 3s
```

While it samples: summon the switcher, cycle through every tile (so every window gets captured),
dismiss, repeat. Do this for the length of the sampling run.

Read the **`IOSurface`** row and **`Physical footprint (peak)`** — not `CG raster data`, not
instantaneous footprint (D8/D12).

## Acceptance

- [ ] With `ThumbnailCacheSize=64` at Retina scale, the `IOSurface` row sampled at summon stays
      under a **stated bound** (propose one from the run — e.g. `64 tiles × observed bytes/tile` —
      and write it into `docs/ARCHITECTURE.md`'s memory rule as the number the bound buys).
- [ ] Lowering the bound (`gotab -prefs ThumbnailCacheSize=16`) visibly lowers the ceiling —
      eviction is releasing `ImageRef`s, not just forgetting keys.
- [ ] Capture timeouts: over the whole run, how many captures hit the 2 s bound? Report the tail; if
      it is non-trivial the timeout is load-bearing, not headroom.
- [ ] Numbers + the chosen bound appended to `docs/DECISIONS.md`; `docs/ROADMAP.md` Phase 0 target
      table ("thumbnail cache") and Phase 6 row updated.

## If the ceiling grows without bound

Eviction is not releasing. Trace `core.Cache`'s `evicted` slice through to
`darwin` `ImageRef.Release` / the prefetcher's `Stop` — a key dropped from the LRU with its bitmap
still held is the exact leak P1.7 exists to prevent (D11 context). Back to P3.3.
