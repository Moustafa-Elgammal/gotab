# P3.3 — Thumbnail rendering via CALayer contents

**Branch:** feat/P3.3  **Phase:** 3  **Depends on:** P1.7 (Cache), P2.6 (Capture), P3.1 (tile layers)
**Owns:** `internal/platform/darwin/thumbnail.h`, `thumbnail.m`, `thumbnail.go`

## Goal

Fill the panel's tiles with thumbnails **after** the panel is already on screen (D12: capture is
~46 ms and cannot happen on the summon path). Each thumbnail is set as a `CALayer`'s `contents` — no
`drawRect:`, no per-tile callback — on the layer P3.1 hands out via `gt_panel_tile_layer(i)`.

When this is done there is a `darwin` entry point the event loop calls after `ShowPanel` that, given
the visible windows and their tile sizes, drives `Capture` + `core.Cache` and sets each tile's image
as it arrives, releasing the ones the cache evicts.

## Contract

Expose (final names yours, this shape):

```go
// Prefetcher fills panel tiles with thumbnails for the given windows, at the given per-tile pixel
// size, and keeps a bounded set live via core.Cache. Start after ShowPanel; Stop on dismiss.
type Prefetcher struct { /* ... */ }
func NewPrefetcher(capacity int) *Prefetcher
func (p *Prefetcher) Want(tiles []ThumbRequest)   // window id + tile index + pixel WxH; non-blocking
func (p *Prefetcher) Stop()                       // cancels in-flight work, releases every live image
```

- **One capture goroutine, not a pool** — D12/D26 measured SCScreenshotManager serialising in the
  WindowServer, so concurrency buys nothing and costs threads.
- Setting `contents` is AppKit and marshals through `darwin.OnMain`. The `CGImage` handed to a layer
  must outlive the layer's use of it — the panel does not retain it (panel.h), so the `Prefetcher`
  holds every `ImageRef` it has handed out and releases on eviction or `Stop`.
- `core.Cache` decides eviction order; this task does the releasing (that split is why `Cache` has no
  cgo). `CacheKey` includes the pixel size — a thumbnail captured for one tile size is not reused at
  another.
- An id that fails capture repeatedly is dropped, not retried forever (D26: 2–10% of captures fail
  because the window is gone or SCK declines).
- `Want` is edit-in-place: called again on a cycle with a new tile set, it captures what is newly
  visible and lets the rest age out of the cache.

## Acceptance

- [~] a thumbnail appears in its tile within a few frames of `Want`, without the panel being re-shown
      — plumbing lands (`gt_thumbnail_set` sets `layer.contents` + `contentsScale`, via `OnMain`), but
      not observed: the responsible process has no Screen Recording grant here, so every `Capture`
      returns `ErrNoRecording`. Needs the grant or a human (V6.4).
- [~] `LiveImages()` returns to the cache bound after a summon completes and tiles evict — not higher
      (this is the assertion `gt_image_adopt` was added for; V6.4 makes it a measurement)
      — same blocker. Logic: each `Capture` success is held in `live` and released exactly once, on
      cache eviction (`drop`) or `Stop`; releases are posted to the FIFO main queue so one can never
      overtake a still-queued `gt_thumbnail_set` for the same handle. `LiveImages()` observed at 0
      throughout a run with no grant (nothing captured) — never negative, never above the bound.
- [~] `Stop` releases every live image: `LiveImages()` back to 0
      — `Stop` returns to 0 in the harness, but with zero images held (no grant). The with-images
      case is deferred to V6.4. `Stop` is idempotent and `Want`-after-`Stop` is a no-op (both run).
- [x] one capture goroutine; `Want` never blocks the caller — one `go p.run()`; `Want` copies the
      slice and does a non-blocking latch poke. 20 back-to-back `Want` calls 5 ms apart did not stall.

## Findings (P3.3 implementation)

**Shape.** `thumbnail.{h,m,go}` added; nothing else touched. `Prefetcher` (`thumbnail.go`):
`NewPrefetcher(capacity) *Prefetcher`, `Want([]ThumbRequest)` (non-blocking, edit-in-place),
`Stop()`. `ThumbRequest{Window, Tile, Width, Height}` — `Width`/`Height` are **pixels** (point size
from `core.Layout` × backing scale), matching `core.CacheKey` and `Capture`'s bound.

**One goroutine.** `NewPrefetcher` starts exactly one `run()`. Not a pool — D12/D26: `SCScreenshotManager`
serialises in the WindowServer. `Want` publishes the new set under a mutex and pokes a depth-1 latch
channel; `run` drains newest-wins and, in `serve`, checks for a superseding set between each capture
so a fast cycle abandons stale work.

**Memory.** Every `Capture` success is held in `live map[core.CacheKey]ImageRef`. `core.Cache.Touch`
drives eviction order; each evicted key → `drop()` → `Release()` exactly once. `Stop` drains the rest
under a `sync.Once`. All `Release()` calls are posted through `OnMain`: the main queue is FIFO and a
key is always *shown* before it can be *evicted*, so the release for a handle is dequeued after every
`gt_thumbnail_set` for it — CoreAnimation's own retain on `layer.contents` covers the gap, so a tile
mid-eviction does not go black. `gt_thumbnail_set` itself moves nothing on `gt_image_live`.

**Failing ids are dropped.** `maxCaptureFails = 3` consecutive failures (D26: "retrying twice
recovered none") marks a window dead for the life of the Prefetcher — a stale cache entry never
self-heals (D26), so there is nothing to retry for. `ErrNoRecording` stops the worker outright rather
than spinning the whole set through the same failure (P4.3 owns that UX).

**Verified** (throwaway `package main`, deleted): builds and links; `Want` never blocks; `Stop` is
prompt and idempotent; `Want` after `Stop` is a no-op; no panic / deadlock / goroutine leak;
`LiveImages()` never negative, never above the bound; `./scripts/check.sh` green.

**Not verified here — needs the Screen Recording grant on the responsible process, or a human (V6.4):**
a thumbnail actually reaching a tile, and `LiveImages()` settling at exactly the cache bound after
real evictions / back to 0 after `Stop` with images held. Under `go run` / a bare binary the
responsible process is the terminal, which lacks the grant, so `Capture` returns `ErrNoRecording`
every time and the capture path cannot be exercised from an agent.

**For the integrator:**
- `thumbnail.go` adds `#cgo LDFLAGS: -framework QuartzCore`. It is genuinely needed (CALayer
  `contents`, and the `kCAGravity*` symbols P3.1's skeleton `panel.m` already references) — without
  it **any** executable linking `internal/platform/darwin` fails at link (the skeleton was already
  broken this way; `go vet`/`go test` don't link, so the gate stayed green). If P3.1 links QuartzCore
  from `panel.go`, the line here becomes redundant, not wrong.
- `Stop()` blocks until an in-flight `Capture` returns. `Capture` has no cancellation and D12 saw it
  hang ~1/10 runs (hence `captureTimeout`), so `Stop` can take up to ~2 s in that rare case, ~57 ms
  normally. If the event loop needs a hard cap on dismiss latency, call `Stop` off the summon path.
- `gt_thumbnail_set` reads the panel's backing scale from `gt_panel_window()` each call and skips
  when `gt_panel_visible()` is 0. It leaves `contentsGravity` to P3.1.
- `Want` is edit-in-place across a cycle. It does **not** learn of a panel tile-count change on its
  own; it re-issues `gt_thumbnail_set` for every requested tile every call (idempotent on the layer),
  which stays correct even if P3.1 rebuilt the tile layers underneath it.
