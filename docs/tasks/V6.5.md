# V6.5 — `internal/platform` behaviour, by driving the built app

**Phase:** 6   **Needs:** a real Mac, both TCC grants, ≥ 20 windows across ≥ 2 apps.
**Discharges:** the P2.5 `assumption` — the `ErrNotTrusted` and no-close-button paths are written
but unrun — and is the runtime check that stands in for the unit tests `internal/platform`
deliberately does not have (docs/ARCHITECTURE.md: it is the humble object; do not chase coverage
there — V6.6 already took the *pure* conversions).

## Goal

Confirm the platform layer does what its `doc.go` claims, end to end, against real windows:
enumerate → order → **raise the window that was actually selected** — and that the documented
failure paths return their sentinels rather than panicking.

## Prerequisites

- `build/GoTab.app`; `gotab -check` shows Accessibility + Screen Recording.
- ≥ 20 windows spread across ≥ 2 apps, including at least one minimized, one hidden-app (⌘H) window,
  and one window whose app has no close button on that window.

## Protocol

1. **Enumerate.** `gotab -list` — the switchable count matches what you can ⌘-Tab / Mission-Control
   to (D19/D21: titled, activation-policy-not-prohibited). `-list -raw` and `-list -ax` show the two
   source sets; the joined list recovers anything AX missed (D20).
2. **Order.** `gotab -watch`, then focus windows in a known sequence — the MRU order tracks it, and
   a title change or resize does **not** reorder (PLATFORM-LESSONS §3).
3. **Raise the selection.** `gotab -switch`. Summon, cycle to a *specific* window (not the first),
   release ⌥. **That** window comes to the front and its app becomes frontmost — not whatever the
   app considered its front window (D25: raise + activate are two halves).
   - Repeat for a **minimized** target: it unminimizes and raises.
   - Repeat for a target in a **hidden** app: it unhides and raises.
4. **Failure paths.**
   - Revoke Accessibility mid-session → the next action returns `ErrNotTrusted` (surfaced via
     `OnError`), the switcher keeps running.
   - Select a window, close it from its app *before* releasing ⌥ → `ErrNoWindow`, switcher dismisses
     cleanly, no panic.
   - `Close` on a window with no close button → `ErrUnavailable`.

## Acceptance

- [ ] Enumerated set matches reality on a ≥ 20-window / ≥ 2-app machine.
- [ ] The selected window — arbitrary position, including minimized and hidden-app cases — is the
      one raised, every time over ~20 trials.
- [ ] All three failure paths return their documented sentinel and the process survives.
- [ ] Findings appended to `docs/DECISIONS.md`; `docs/ROADMAP.md` Phase 6 row → ✅, P2.5's
      `assumption` marked discharged.

## Notes

This is verification by driving the app, not a new test suite — resist adding `_test.go` under
`internal/platform`. If a pure helper surfaces that *could* be table-tested, it belongs with V6.6's
set, not here.
