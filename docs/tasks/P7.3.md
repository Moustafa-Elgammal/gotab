# P7.3 — Space-aware raise (optional, private-API)

**Phase:** 7  **Depends on:** P7.1 (the raise fallback it sits in front of), P2.4 / D24 (SkyLight
via `dlopen`/`dlsym`)  **Owns:** `space.h`, `space.m`, and the P7.3 hook + doc comments in
`action.{h,m,go}`

## Goal

P7.1 made an un-resolvable window's *application* come forward. P7.3 tries to do better for the
common cause — the window is genuinely on another Space, where `kAXWindowsAttribute` cannot see it
(D20 / D46) — by switching to that Space first and then resolving the window normally, so P7.1's
app-only fallback becomes the exception rather than the rule.

This is **optional** and a **private-API bet**: it drives SkyLight symbols Apple never documented. A
macOS release that removes them degrades this back to P7.1's floor — it must never break the build or
the raise path.

## Contract

- New C function, declared in `space.h`, defined in `space.m`:
  `int gt_space_switch_to_window(uint32_t wid)` — if `wid` is on a Space other than the current one,
  make that Space current and return `1`; return `0` in every other case (SkyLight absent, the write
  symbols absent, the window's Space unknown or already current, the switch did not take).
- SkyLight symbols added to `space.m`'s existing `dlopen`/`dlsym` block — **no link flag, no `#cgo`
  change, no `shim.*` edit** (D24's rule):
  - `CGSCopyManagedDisplayForSpace` / `SLSCopyManagedDisplayForSpace` — the display a Space is on.
  - `CGSManagedDisplaySetCurrentSpace` / `SLSManagedDisplaySetCurrentSpace` — the actual switch.
  - `CGSShowSpaces` / `CGSHideSpaces` (+ `SLS` aliases) — the reveal animation, **best-effort**: if
    absent, `SetCurrentSpace` is still called (the pointer moves; some macOS versions just cut).
  - `CGSMainConnectionID` and `CGSCopySpacesForWindows` were already loaded (P2.4).
  None of these join `g_sl.loaded`'s minimum — the read queries must keep working for the rest of the
  package regardless; `gt_space_switch_to_window` checks the symbols it needs itself.
- `gt_window_raise` (`action.m`): after `copy_window_element` returns no element with
  `st == GT_ERR_NO_WINDOW`, call `gt_space_switch_to_window(wid)`; on `1`, re-run
  `copy_window_element` and, if it now resolves, raise the real window through the normal body
  (unminimize check → `kAXMain`/`kAXFocused` → `kAXRaiseAction` → `activate_app`). On `0`, or if the
  retry still fails, fall through **unchanged** to P7.1's `app_is_alive` / `activate_app`. The call
  is short-circuited behind `!win && st == GT_ERR_NO_WINDOW`, so the normal raise path never touches
  SkyLight.
- `Raise`'s Go signature is unchanged. `Minimize` / `Unminimize` / `Close` are untouched.

`assumption` (discharged by V6.2): that `CGSManagedDisplaySetCurrentSpace` + the display lookup +
optional Show/Hide is enough to both move the current-Space pointer **and** reveal it, and that
`copy_window_element` sees the window immediately after the switch rather than needing a settle delay.
Written on a **one-Space machine** (D24) — the cross-Space path is reasoned from how yabai and
Hammerspoon drive the same calls, not observed.

## Findings

_On-machine verification pending (V6.2 / V6.13, a human with ≥ 2 Spaces). Record here: whether the
bare `SetCurrentSpace` transitions visibly or needs Show/Hide; whether the immediate re-resolve is
too eager (a settle delay / bounded retry may be needed); which spelling (`CGS` vs `SLS`) resolved;
and whether the switch survives the current macOS version at all._

Design notes taken while writing it:

- **`gt_space_switch_to_window` returns `1` only after re-reading `gt_current_space()` and confirming
  it equals the target.** The caller uses that as "the retry is worth it"; a switch that silently
  did nothing must not send `gt_window_raise` into a pointless second AX scan.
- **A window reported on the current Space (assigned to All Desktops, or mid-drag) returns `0`** — it
  is already visible, there is nothing to switch to, and P7.1's path (or the normal resolve) covers
  it.
- **Show/Hide are deliberately optional, not required symbols.** They are the two most likely to
  move or vanish; gating the whole feature on them would make it more fragile than it needs to be.
  If V6.2 shows the bare `SetCurrentSpace` does not reveal, promote them to required then.
- **No settle delay after the switch.** Sleeping inside a cgo call on the event-loop goroutine is
  worse than the failure it would paper over: if the re-resolve races the transition, the code
  falls through to P7.1 and still activates the app on the now-correct Space. V6.2 decides whether a
  bounded retry is worth adding.
- P7.4 records the standing default (keep showing app-reachable windows); P7.3 only changes how often
  the app-only path is the one taken.
