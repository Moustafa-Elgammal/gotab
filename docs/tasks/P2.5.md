# P2.5 — Actions: raise, focus, minimize, close

**Phase:** 2  **Depends on:** P2.3a  **Owns:** `action.h`, `action.m`, `action.go`

## Goal

Make a window actually come to the front. This is the first thing that turns the project from an
enumerator into a switcher.

## Files you may touch

- `internal/platform/darwin/action.h`, `action.m`, `action.go` — **yours alone**
- `docs/tasks/P2.5.md` (tick acceptance, record findings)

**Do not touch** `shim.h`, `shim.m`, `shim.go`, `window.go`, `internal/app/`, `cmd/gotab/`,
`docs/ROADMAP.md`, `docs/DECISIONS.md`.

## Contract

```go
func Raise(id core.WindowID) error       // bring to front AND activate its application
func Minimize(id core.WindowID) error
func Unminimize(id core.WindowID) error
func Close(id core.WindowID) error
```

## Acceptance

- [x] `Raise` on a background window brings it to front and makes its app frontmost
      — 5/5 across Finder, Docker Desktop and Google Chrome; verified against `lsappinfo front` for the
      application and `System Events ... window 1` for the window inside it, so both halves are checked
      separately. 8-13 ms.
- [x] `Raise` on a **minimized** window unminimizes it first — a switcher that selects a minimized
      window and does nothing is broken
      — 5/5 on a Finder window minimized while another app was frontmost: unminimized, frontmost within
      Finder, Finder frontmost, `nil` error, 33-39 ms. Also 3/3 for the neighbouring case, a window of
      an application hidden with ⌘H: `[NSRunningApplication unhide]` then activate, frontmost at +0.4 s.
- [x] a window that vanished between enumeration and action returns an error, not a panic
      — all four entry points return `ErrNoWindow` for synthetic ids (0, 1, 999999999) and for a real id
      observed alive and then closed out from under the process. ~24 ms per failed lookup, which is the
      cost of the fallback scan. No panic, no hang.
- [x] `./scripts/check.sh` green
      — gofmt, vet, tests, core-purity all ok. No tests were added (D16).

Not verified, and why:

- **The `ErrNotTrusted` path.** Every entry point refuses up front on `AXIsProcessTrusted()`, but the
  terminal holds the Accessibility grant on this machine and revoking it to prove the branch would have
  cost the rest of the session. The guard is the same one `gt_ax_window_list` already uses.
- **`ErrUnavailable` from `Close` on a window with no close button.** The branch is written and reviewed;
  no window without a close button was available to press it against.

## Findings

**`kAXRaiseAction` never answers during the Dock's restore animation.** Measured on macOS 26.6.2, four
trials per variant. Raising a just-unminimized window burns the full `GT_ACTION_TIMEOUT_SEC` and returns
`kAXErrorCannotComplete` (-25204) — 251-255 ms, against 0.2-0.4 ms for the unminimize and the `kAXMain`
and `kAXFocused` writes around it. The action still lands; only the reply is missing. So the raise gets a
20 ms messaging timeout on that one path and `kAXErrorCannotComplete` is read as success there. Same 4/4
correctness, 28-35 ms instead of 258-292 ms.

**Restoring from the Dock does not raise the window inside its application.** Skipping `kAXRaiseAction`
when the window was minimized is the obvious way to dodge the timeout above, and it is wrong: 0/4 trials
put the restored window at the front of its app, while 4/4 still made the app frontmost. The two halves
of a switch really are independent, and this is the case that shows it.

**Activation must not hang off the raise.** The first version returned early when the raise failed, which
meant every minimized window hit the timeout above and then never activated: the user watched the window
un-minimize behind whatever they were trying to leave. `activate_app` now runs whatever the raise
returned — the half the user can see does not depend on the half they cannot.

**`CGWindowListCopyWindowInfo` reports windows that are already closed.** Finder windows closed through
this API stayed in the CG list (and therefore in P2.3c's joined enumeration) while AX had already dropped
them. This cost an hour of chasing a `Close` that looked broken and was not: closing is 3/3 measured
against the AX window count. It matters to the caller as well — a stale id resolves to a pid through
`pid_for_window` and only the AX scan behind it discovers there is no window, which is exactly why the
fallback exists rather than trusting CoreGraphics.

**`activateWithOptions:` needs no options on macOS 14+.** `NSApplicationActivateIgnoringOtherApps` is
deprecated and inert there; `activateWithOptions:0` from a background, Accessibility-trusted process
activated the target every time. The pre-14 branch is kept because the deployment target is 12.0 (D17)
and is not exercised on this machine.

**`GT_ERR_NO_WINDOW = 6` extends `shim.h`'s status enum from `action.h`.** `shim.h` is frozen, and the
race this task is written around had no status. If another Phase 2 task adds a status of its own, the two
numbering spaces must be reconciled — the closed enum is still the design.

## Notes

Finding the `AXUIElement` for a `CGWindowID` is the core problem: AX has no public lookup, so you must
walk `kAXWindowsAttribute` of the owning application and match with `_AXUIElementGetWindow`, which
`shim.m` already declares. Read how `gt_ax_window_list` does it — you may **call** nothing from shim.m,
but you may copy the two-line pattern.

Raising is two steps and both are needed: `AXUIElementPerformAction(win, kAXRaiseAction)` orders the
window within its app, and `[NSRunningApplication activateWithOptions:]` makes the app frontmost.
Neither alone is a switch.

Every AX call is Mach IPC into a possibly unresponsive app. `AXUIElementSetMessagingTimeout` — see
`GT_AX_TIMEOUT_SEC` in `shim.m` for the value already chosen.
