# P2.2 — Batched window query: one call, one packed array

**Branch:** main (Phase 2 is serial)   **Phase:** 2   **Depends on:** P1.0, P1.1, P2.1

## Goal

One cgo crossing returns every window the WindowServer knows about, as a packed array of fixed-size
records, which Go turns into `core.Window` values ready for `core.Model`. This is the discipline in
`ARCHITECTURE.md#the-cgo-rule` made concrete: never a call per window, never a call per field.

## What has to be answered

1. **Where does the flag vocabulary live?** `core.WindowFlags` is frozen (P1.0). Mirroring those bits in
   C would be two definitions of one thing, which is what `AGENTS.md` says makes copies drift.
2. **What does `CGWindowList` actually know, and what does it not?** Minimized, hidden, Space and tab
   group are not in it. The record must not pretend otherwise — an unset flag that means "unknown" and
   an unset flag that means "false" are different, and confusing them is how a switcher hides a window.
3. **How do variable-length titles cross a fixed-size record** without a per-window allocation in C or
   a second crossing?

## Acceptance

- [x] one `gt_window_list` call returns N windows; the number of crossings does not grow with N
- [x] `core.Window` values come back with ID, App, AppName, Title and `FlagOnScreen`. Minimized,
      Hidden, Fullscreen, Tabbed, Space and focus order are left clear — unset means *not known yet*
- [x] a title longer than the record's buffer truncates on a character boundary, not a byte
- [x] the caller's buffer is reused across calls; growth retries, and a list that outruns four
      attempts returns the windows it got **with** `ErrTruncated` rather than a short list that looks
      complete
- [x] `./scripts/check.sh` green, purity gate included

Per D16 this task writes no tests; `internal/platform` is not unit-tested at all (ARCHITECTURE.md).

## Notes

**Titles need Screen Recording.** Without that grant `kCGWindowName` is absent for other apps' windows
and every title comes back empty — the app is not broken, it is unpermitted, and the two must be
distinguishable from the returned data. AX titles (P2.3) are the fallback.

**`kCGWindowLayer != 0` is not a window.** Menubar items, the Dock, shadows and overlays all come back
from `CGWindowListCopyWindowInfo`. Excluding them is a platform fact about what the API returns, not a
user preference — user preferences are `core.Rules` and belong to P1.3, which has already shipped.

## Known gap, deliberately not closed here

`gt_window` carries `alpha`, and Go ignores it. A fully transparent window is not switchable, but
`core.Window` has no field to carry that and `internal/core/api.go` is frozen — adding one is an
escalation, not an edit (AGENTS.md). Recorded rather than resolved quietly. D19 makes it moot in
practice: P2.3's AX enumeration will not return these windows at all.
