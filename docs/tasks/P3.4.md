# P3.4 — Theme / appearance / dark mode

**Branch:** feat/P3.4  **Phase:** 3  **Depends on:** P3.1 (palette + material setters)
**Owns:** `internal/platform/darwin/theme.h`, `theme.m`, `theme.go`

## Goal

Decide the panel's colours and vibrancy from the system's **effective appearance**, apply them through
the two frozen setters P3.1 exposes (`gt_panel_set_palette`, `gt_panel_set_material`), and keep them
in step when the user switches Light/Dark mid-session. The panel should look native in both, and never
flash an unstyled frame.

## Files you may touch

- `internal/platform/darwin/theme.h`, `theme.m`, `theme.go` — yours alone.
- `docs/tasks/P3.4.md` (this file)

**Do not touch** `panel.*` (P3.1 — call its frozen accessors/setters, add nothing to it), `shim.*`,
`thumbnail.*` (P3.3), `internal/core/`, `internal/app/`, `cmd/gotab/`, `docs/ROADMAP.md`,
`docs/DECISIONS.md`.

## Contract

Expose (final names yours, this shape):

```go
// ApplyTheme reads the current effective appearance and pushes a palette + material to the panel.
// Safe to call before or after CreatePanel; a call before is remembered and replayed.
func ApplyTheme() error

// WatchAppearance calls onChange (which should call ApplyTheme) whenever the effective appearance
// flips. onChange runs on the main thread and must return immediately. StopWatchingAppearance ends it.
func WatchAppearance(onChange func()) error
func StopWatchingAppearance()
```

- Read the effective appearance from `NSApp.effectiveAppearance` (or the panel's, via
  `gt_panel_effect_view()`), matched against `NSAppearanceNameDarkAqua` — not `AppleInterfaceStyle`
  from user defaults, which misses the per-app override and the auto Light/Dark schedule.
- Build the `gt_palette` for each appearance. The colour *choices* may live on the Go side of this
  task; the reading and the KVO/notification observing are ObjC in `theme.m`.
- Pick the `NSVisualEffectMaterial` (a `HUD`-ish material reads right for a floating switcher). Pass
  `GT_MATERIAL_NONE` to fall back to `palette.panel_bg` if you decide vibrancy is wrong here.
- The appearance observer callback does nothing but call `onChange` — same rule as P2.3b's observers
  (`ARCHITECTURE.md#the-cgo-rule`).
- No leaked observer / KVO registration on `StopWatchingAppearance`.

## Notes

`gt_panel_set_palette` / `gt_panel_set_material` are frozen in `panel.h`. If you find you need another
knob from P3.1 (a per-tile accent, a corner radius), **stop and escalate** — that is a `panel.h`
change and belongs to the integrator, exactly as an `api.go` change did in Phase 1.

Before `gt_panel_create`, the setters no-op safely (skeleton behaviour) — `ApplyTheme` called early
must still take effect once the panel exists, so remember the last palette/material and replay it, or
have the integrator call `ApplyTheme` right after `CreatePanel` (say which in Findings).
