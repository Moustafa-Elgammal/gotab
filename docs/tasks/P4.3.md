# P4.3 — Permissions onboarding

**Phase:** 4  **Depends on:** P3.5 (the hotkey needs Accessibility), P4.1 (`-check` exists)
**Owns:** `internal/platform/darwin/permissions.{h,m,go}`, `-permissions` + `ensurePermissions` /
`promptForGrants` / `stderrIsTTY` in `cmd/gotab/main.go`, and the deep links in `reportPermissions`

## Goal

When a grant is missing, name it, say what it is for, send the user to the right System Settings pane,
and pick the grant up **without a relaunch**. Accessibility is mandatory; Screen Recording is a
degrade-with-a-warning.

## Contract

- `gt_permissions_prompt(need_ax, need_sr)` — a modal `NSAlert` naming the missing grants; on "Open
  System Settings" it opens the pane(s) and, for Screen Recording, calls
  `CGRequestScreenCaptureAccess` (registers the app in that list). Returns GT_OK (proceed),
  GT_ERR_UNAVAILABLE (user quit), or GT_ERR_INTERNAL (no window server → caller prints instead).
- `darwin.PromptPermissions` → `(shown, proceed bool)`; `darwin.OpenPrivacyPane("accessibility" |
  "screen-recording" | "")`.
- `gotab -permissions` — report, prompt for what's missing, then poll `CheckPermissions` until it
  appears (^C stops). `gotab -switch` gates on Accessibility the same way, with a 5-minute cap.
- `gotab -check` prints the `x-apple.systempreferences:` deep links for the missing grants.

## Acceptance

- [x] `-check` names each missing grant and prints its Settings deep link
- [x] `-permissions` reports state; if something is missing it prompts, opens the pane, and waits,
      announcing each grant as it flips; exits 0 once both are in place
- [x] `-switch` will not start without Accessibility — it onboards and waits (5 min, then quits with
      "re-open after granting"); Screen Recording missing is a one-line warning and it runs on
- [x] the wait loop recovers with no relaunch: a poll on `CheckPermissions`, so a grant toggled in
      Settings is picked up within ~1 s. macOS relaunching gotab on an Accessibility grant is also
      fine — the fresh process passes the gate and never prompts
- [x] headless-safe: with no window server the alert is skipped (`[[NSScreen screens] count] == 0` →
      GT_ERR_INTERNAL) and the caller falls back to printed links; the poll loop is `ctx`-cancellable
- [x] `./scripts/check.sh` green; `scripts/build.sh` produces the universal app

## Findings

- **Modal from Finder, text from a shell.** `stderrIsTTY()` decides: a `.app` double-clicked from
  Finder has no controlling terminal, so the `NSAlert` is the only channel; from a shell an alert
  stealing focus for text the user can read inline is worse than a printed block, so the TTY path
  prints the deep links and opens the pane directly. Verified the TTY path via a pty — prints, opens
  the pane, enters the poll, and ^C exits it cleanly.
- **`[NSAlert runModal]` cannot be interrupted** and blocks forever with nothing to answer it, so the
  headless guard is not optional. A first attempt without it hung under `kill -INT` and needed
  `kill -9`. With `[[NSScreen screens] count] == 0` the C side returns GT_ERR_INTERNAL and the Go
  caller prints instead.
- **The recovery is a poll, not an observer.** TCC has no "grant changed" notification worth relying
  on; a 750 ms poll on `gt_trusted()` / `gt_can_record()` is simple and fast enough. `-switch` caps
  it at 5 minutes then quits with a re-open hint; `-permissions` waits until ^C because the user
  asked for it.
- **Screen Recording registration.** `CGRequestScreenCaptureAccess()` both shows its own dialog and
  adds the app to the Screen Recording list so there is a row to toggle. Without ever calling it (or
  attempting a capture) the app would not appear there. The modal path calls it; the TTY path relies
  on the prefetcher's first capture attempt doing the same.
- **No new window.** An `NSAlert` needs no controller class, no layout, no timer-in-window — the
  onboarding "UI" is the alert plus the System Settings pane, which is the native pattern.
