## Goal

`core.Layout` computes the panel size and every tile frame from a window count and the screen it will
appear on. Pure geometry: **"pure Go computes frames, C only draws"** (ROADMAP P3.2). The renderer
(P3.1) consumes the output verbatim — it does no arithmetic of its own.

The skeleton is one row of equal tiles clamped to the screen width. Replace the body of `Layout` with
the real engine.

## Contract

Keep the `Layout` signature and the `Rect` / `LayoutOpts` / `Result` shapes. **Extend by adding
fields, never by renaming or reshaping** — P3.1 and the integrator code against them. `Layout` must:

- wrap to multiple rows once tiles would overflow the usable width (or `MaxCols` is hit), and size the
  panel height to the row count
- honour a **minimum and maximum tile size** in points — shrink-to-fit has a floor, below which it
  wraps instead; grow-to-fill has a ceiling
- keep the panel inside `Screen` with a margin that is sensible on both a 1280-wide and a 6016-wide
  display (a fixed 80 px looks wrong on one of them)
- return exactly `n` tile `Rect`s, index-aligned to the caller's window order, origin top-left
- allocate nothing when handed a big-enough `dst` (`dst[:0]`); the switcher reuses one backing slice
  across summons and the hot path must stay 0 allocs/op
- be **deterministic** — same inputs, same output, every call

`n == 0` returns an empty-slab panel and `len(Tiles) == 0`. `Scale` is echoed through unchanged.
