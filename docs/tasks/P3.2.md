## Goal

`core.Layout` computes the panel size and every tile frame from a window count and the screen it will
appear on. Pure geometry: **"pure Go computes frames, C only draws"** (ROADMAP P3.2). The renderer
(P3.1) consumes the output verbatim — it does no arithmetic of its own.

The skeleton is one row of equal tiles clamped to the screen width. Replace the body of `Layout` with
the real engine.

## Contract

Keep the `Layout` signature and the `Rect` / `LayoutOpts` / `Result` shapes. **Extend by adding
fields, never by renaming or reshaping** — P3.1 and the integrator code against them. `Layout` must:

- wrap to multiple rows once tiles would overflow the usable width (or `MaxCols` is hit), and size the
  panel height to the row count
- honour a **minimum and maximum tile size** in points — shrink-to-fit has a floor, below which it
  wraps instead; grow-to-fill has a ceiling
- keep the panel inside `Screen` with a margin that is sensible on both a 1280-wide and a 6016-wide
  display (a fixed 80 px looks wrong on one of them)
- return exactly `n` tile `Rect`s, index-aligned to the caller's window order, origin top-left
- allocate nothing when handed a big-enough `dst` (`dst[:0]`); the switcher reuses one backing slice
  across summons and the hot path must stay 0 allocs/op
- be **deterministic** — same inputs, same output, every call

`n == 0` returns an empty-slab panel and `len(Tiles) == 0`. `Scale` is echoed through unchanged.

## Findings

### What the engine does

`Layout` now runs four steps, all integer arithmetic:

1. **Margin scales with the display.** `margin = clamp(Screen.W / 20, 32, 220)`. 1280 → 64, 2560 →
   128, 6016 → 220 (clamped). This is the only thing that keeps the panel off the bezel on a laptop
   without swallowing a Pro Display XDR — a fixed 80 pt fails one end or the other. `Screen`'s origin
   is ignored; the renderer centres the panel on the display under the mouse itself (`gt_panel_show`).
2. **Columns = how many `MinTileW` tiles fit the usable width**, then capped by `MaxCols` and `n`,
   floored at 1. The minimum-size floor is enforced *here*, by not placing more per row than fit at
   `MinTileW` — "below the minimum it wraps instead" rather than shrinking tiles past the floor.
3. **Tile width = usable width ÷ columns, clamped to `[MinTileW, MaxTileW]`.** A sparse row grows its
   tiles toward `MaxTileW` and then stops reaching the screen edges; it never exceeds the ceiling.
4. **Rebalance.** With the row count fixed, `cols = ceil(n / rows)` so a trailing row is never left
   nearly empty (12 windows on a 1280 display → 6+6, not 10+2). `ceil(n/rows) ≤ cols_before` always,
   so this only shrinks `cols` — it can never break `MaxCols` or the width fit.

Tile height is `clamp(TileH, MinTileH, MaxTileH)`, constant for every tile — a *row* stretches
horizontally, a column does not. `Panel.H = 2·panelPad + rows·tileH + (rows−1)·gap`.

### Contract shape — fields ADDED, nothing renamed or reshaped

- `LayoutOpts`: `MinTileW, MinTileH, MaxTileW, MaxTileH int` (zero → built-in default). Defaults are
  `96×72 .. 280×210` around the frozen `160×120` preferred, all 4:3.
- `Result`: `Cols, Rows int` (the grid the integrator moves the selection across without re-deriving
  it) and `Overflow bool` (panel taller than `Screen.H` — see below). `Panel`, `Tiles`, `Scale` keep
  their name, type and position; P3.1 is unaffected.
- New consts: `DefaultMinTileW/H`, `DefaultMaxTileW/H`, `marginDivisor`, `minMargin`, `maxMargin`.
  `DefaultTileW/H`, `tileGap`, `panelPad` are untouched (P3.1's placeholder art shares them).

### How wrap / clamp / scale / 0-alloc were convinced of

Checked out-of-tree (throwaway `package main` under a temp dir, run with `go run`, then deleted — no
test file added, D23). Representative results:

| case | result |
|---|---|
| 1280 w, 8 win | 1 row, tiles ≈131 pt (between pref and min) |
| 6016 w, 8 win | 1 row, tiles = 280 pt (**MaxTileW ceiling hit**), panel 2342 pt wide, centred |
| 1280 w, 12 win | **wraps** to 6+6, panel 2 rows tall |
| 1280 w, 40 win | wraps to 10×4, tiles ≈103 pt (near the **MinTileW floor**, does not go under) |
| 1280 w, 10 win, `MaxCols=4` | **wraps** to 4+4+2 |
| n = 0 | `Panel = 32×32`, `len(Tiles) == 0`, `Cols=Rows=0` |
| `Scale: 2` | echoed unchanged |

0-alloc: `testing.Benchmark` with `b.ReportAllocs()` and a reused `dst[:0]` (cap 256) reports
**0 allocs/op, 0 B/op** for n = 0, 1, 8, 30, 50. The only `make` is guarded by `cap(dst) < n`; the
rest is stack scalars, one value-returned `Result`, and `append` into pre-capacity. `nil` dst
allocates exactly once (640 B for n = 20). Determinism: 1000 calls with a fixed `LayoutOpts` compared
field-by-field, all identical — no maps, no `time`, no `rand`.

### Cases V6.6 / V6.8 should pin

- **V6.8 — 0 allocs/op.** Bench `Layout` with a presized `dst[:0]` across n ∈ {0, 1, 8, 30, 50} and a
  real `Screen`; assert `AllocsPerOp() == 0`. Separately assert the `nil`-dst path allocates once.
- **V6.6 — index alignment / row-major.** For `Cols > 0`, tile `i` must have `X == panelPad +
  (i%Cols)·(W+gap)` and `Y == panelPad + (i/Cols)·(H+gap)`; `len(Tiles) == n` exactly, including
  `n == 0`.
- **V6.6 — the min/max boundary.** Pick `Screen.W` and `MinTileW` so `k` tiles fit but `k+1` do not;
  `n == k` stays one row, `n == k+1` wraps. And a wide `Screen` with small `n` must clamp `tileW` to
  exactly `MaxTileW`, not overshoot.
- **V6.6 — margin scaling.** `margin(1280) == 64`, `margin(2560) == 128`, `margin(6016) == 220`
  (clamped); the panel always fits inside `Screen.W` for any `n` at or above the `MinTileW` fit.
- **V6.6 — rebalance.** `n == 7`, 2 rows ⇒ `Cols == 4` (4+3), never 5+2.
- **V6.6 — determinism.** Same `LayoutOpts` + n ⇒ identical `Result` (panel, grid, every tile).
- **V6.6 — `Overflow` / pathological inputs.** `Overflow` is set (never a dropped tile) when
  `rows·tileH + chrome > Screen.H`. Layout still emits all `n` tiles; clip/scroll is the renderer's.
  Also: `MinTileW > MaxTileW` is coerced (both become the larger) and a sub-`MinTileW` display width
  drops the tile below the floor **to keep the panel on `Screen`** rather than hang it off the bezel —
  no real macOS display reaches this, but the behaviour is deliberate and should be pinned.

### assumption (tag at V6.6)

- **Selected-tile emphasis was left out.** The task marks it optional ("*If* you add a `SelectedRow
  int`…"). It is not implemented, so `LayoutOpts` has no such field yet and every tile in a row is
  equal width. When it lands: add `SelectedRow int` after `MaxCols`, with `< 0` meaning "no emphasis"
  (the zero value is a valid tile index, so the sentinel must be negative — unlike `Rules.ActiveApp
  == 0`); widen that one tile and give its row the taller height, keeping `len(Tiles) == n` and the
  row-major index alignment. V6.6 should pin `SelectedRow < 0` and an out-of-range `SelectedRow` as
  no-ops.
- **Height does not track width.** When `tileW` is driven well below `TileW` on a narrow display, the
  tile aspect ratio departs from `TileW:TileH` and a thumbnail drawn to fill it would distort. Left
  to P3.1/P3.3 (aspect-fit within the frame). If that proves wrong, `tileH` should follow the chosen
  `tileW` by the preferred ratio, then clamp to `[MinTileH, MaxTileH]`.
