# P2.6 — Thumbnail capture with explicit C-side lifecycle

**Phase:** 2  **Depends on:** P1.7, P2.1  **Owns:** `capture.h`, `capture.m`, `capture.go`

## Goal

Capture a window thumbnail through ScreenCaptureKit and hand Go an opaque handle it must release.

## Files you may touch

- `internal/platform/darwin/capture.h`, `capture.m`, `capture.go` — **yours alone**
- `docs/tasks/P2.6.md` (tick acceptance, record findings)

**Do not touch** `shim.h`, `shim.m`, `shim.go`, `window.go`, `internal/app/`, `cmd/gotab/`,
`docs/ROADMAP.md`, `docs/DECISIONS.md`.

## Contract

`ImageRef` and `gt_image_release` already exist in `shim.go`/`shim.h` and are **frozen** — you produce
handles, you do not redefine how they are freed.

```go
// Capture grabs one window at up to maxWidth px. Blocking, time-bounded, and failable.
```

## Acceptance

- [ ] a capture returns a live `ImageRef`; `Release()` frees it and `LiveImages()` returns to 0
- [ ] a capture that does not answer times out and returns an error rather than hanging
- [ ] thumbnails are **downscaled at capture time**, never captured full-res and shrunk
- [ ] `./scripts/check.sh` green

## Notes

**Read `spike/sck/` first — it already solved this.** D12 and D14 are its findings: capture is ~46 ms
warm / ~112 ms cold, it does **not** parallelise, the completion handler fires on a Go-owned thread with
no run loop (so no AppKit marshalling is needed), output is IOSurface-backed, and `CGImageRelease` alone
is sufficient with no separate IOSurface step.

**D12: capture cannot happen on the summon path.** ~46 ms against a 100 ms budget. This API is for
capturing *ahead* of a summon; do not design it as something the summon path calls.

`spike/sck` notes ScreenCaptureKit is hard-linked because cgo rejects `-weak_framework` without
`CGO_LDFLAGS_ALLOW`. SCK arrives in macOS 12.3 and this project's floor is `minos 12.0` (D17), so a
hard link makes the binary refuse to load on 12.0–12.2. Weak-linking is the correct answer; if you need
`CGO_LDFLAGS_ALLOW`, **say so in your report** — `scripts/build.sh` is the integrator's file, not yours.
