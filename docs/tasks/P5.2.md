# P5.2 — VoiceOver / accessibility

**Branch:** feat/P5.2   **Phase:** 5   **Depends on:** P3.1 (the panel and its content view), P4.2
(the settings window)

## Goal

A VoiceOver user can operate the switcher and the settings window. The panel exposes its tiles as
accessibility elements — each labelled with its window title and app — and announces the selected
window as the user cycles, so switching by ⌥⇥ is usable without sight of the screen. Every control in
the settings window has a spoken label.

## The problem to solve in the panel

`panel.m` draws every tile itself into one flipped content view (`panel.h`): there are no per-tile
`NSView`s for AppKit to hand VoiceOver. So the content view must implement the `NSAccessibility`
informal protocol:

- `isAccessibilityElement` → NO on the content view itself; it is a container.
- `accessibilityRole` → `NSAccessibilityGroupRole` (or `NSAccessibilityListRole`), with a
  `accessibilityLabel` of "Window switcher".
- `accessibilityChildren` → one `NSAccessibilityElement` (or a small custom element class) per tile,
  built from the `gt_tile` array `panel.m` already retains to redraw. Each child:
  - `accessibilityFrameInParentSpace` (or `accessibilityFrame`) = the tile's `x/y/w/h`.
  - `accessibilityRole` = `NSAccessibilityButtonRole` (activating it is "raise this window").
  - `accessibilityLabel` = `"<title>, <subtitle>"` from the tile (`title_len` / `subtitle_len` bytes);
    when `title` is empty fall back to just the app name.
  - reflects `selected` through `isAccessibilitySelected`.
- On the selection-change path — inside the `gt_panel_update` body, and the first `gt_panel_show` —
  post an announcement for the newly selected tile so VoiceOver speaks it immediately:
  `NSAccessibilityPostNotificationWithUserInfo(contentView,
  NSAccessibilityAnnouncementRequestedNotification, @{NSAccessibilityAnnouncementKey: label,
  NSAccessibilityPriorityKey: @(NSAccessibilityPriorityHigh)})`, and/or
  `NSAccessibilityPostNotification(child, NSAccessibilitySelectedChildrenChangedNotification)`. Rebuild
  or refresh the children array whenever the tile count or selection changes; post
  `NSAccessibilityLayoutChangedNotification` when the set changes.

Keep all of this inside `panel.m`. `panel.h` is frozen — you should not need a new exported function;
if you genuinely do, that is the one allowed escalation (P5.2 is the only Phase-5 task in `panel.*`),
note it in Findings.

## Notes

No tests (D23) — `internal/platform` is the humble object and is not unit-tested (ARCHITECTURE.md).
`panel.m` is compiled without ARC: an `NSAccessibilityElement` you `alloc` you must `release` (retain
the children array on the content view and release it when you rebuild). Match the memory discipline
already in `panel.m`.

## Findings

- **Panel — the content view is the container.** `GTTileView` (which draws every tile) now answers
  `isAccessibilityElement` NO, `accessibilityRole` `NSAccessibilityGroupRole`, `accessibilityLabel`
  "Window switcher", and `accessibilityChildren` / `accessibilitySelectedChildren` from a file-static
  `g_a11y_children`. Each child is a `GTTileElement : NSAccessibilityElement` with role
  `NSAccessibilityButtonRole`, a `"<title>, <app>"` label (`a11y_label()` — falls back to the app
  name, then to "Untitled window", so an element is never silent), an
  `accessibilityFrameInParentSpace` set to the tile's own top-left `x/y/w/h`, and
  `isAccessibilitySelected` from a `@public BOOL tileSelected`.
- **`accessibilityFrameInParentSpace`, not `accessibilityFrame`.** `NSAccessibilityElement` does the
  flipped-parent conversion itself, so the elements use the exact frame `drawRect:` uses — no manual
  flip, no divergence between what is drawn and what is reported.
- **Announcement path.** `panel_populate` (the shared body of `gt_panel_show` and `gt_panel_update`)
  now finds the selected index, calls `a11y_sync()` to bring `g_a11y_children` to the tile count and
  refresh every label/frame/selected, then: posts `NSAccessibilityLayoutChangedNotification` when the
  count changed, and posts `NSAccessibilityAnnouncementRequestedNotification` (priority High) +
  `NSAccessibilitySelectedChildrenChangedNotification` when the selection moved *or* the count
  changed. `g_a11y_last_selected` / `g_a11y_last_n` debounce it so a no-op redraw (a thumbnail
  arriving, a palette flip) is silent; `gt_panel_hide` resets them to `-1` so the next summon always
  speaks its initial selection even when it matches the previous one. All of it is inert when
  VoiceOver is not running.
- **Press is a no-op, deliberately.** `panel.h` exposes no Go callback to raise a window from
  `panel.m`, and it is frozen. `GTTileElement.accessibilityPerformPress` returns NO; activation still
  travels the ordinary path (release the modifier → the hotkey tap → `Loop.Activate` → `darwin.Raise`),
  which a VoiceOver user does exactly as a sighted user does. Wiring press-to-raise would need a new
  exported function — a follow-up, noted here rather than escalated, since the cycle-and-release flow
  is already usable without sight.
- **Memory (no ARC).** `g_a11y_children` is alloc'd once and lives for the process, like
  `g_tile_layers`. Each `GTTileElement` is `alloc`/`init` (+1), `addObject` (+1), `release` (→ owned
  by the array); a shrink `removeLastObject`s the tail. `accessibilityChildren` hands out
  `[[g_a11y_children copy] autorelease]` so a screen reader never holds the mutable array while
  `a11y_sync` mutates it. The refresh block in `panel_populate` is wrapped in `@autoreleasepool`,
  matching `drawRect:`.
- **Settings — labels on the controls that render no text of their own.** `setAccessibilityLabel:`
  on the two steppers (their caption, e.g. "Columns before wrapping" / "Thumbnail cache (images)" —
  the value still reaches VoiceOver via the stepper's `integerValue`), the Appearance popup ("Panel
  appearance"), the blocked-apps field ("Never show these apps, comma-separated application names"),
  and the hotkey recorder ("Keyboard shortcut", with the chord riding as the button title/value).
  The four filter checkboxes already speak their own titles and were left alone, per the contract.
  `add_text` gained an `axLabel` parameter (one caller).
- **Gate + build.** `./scripts/check.sh` green; `./scripts/build.sh` produces the signed universal
  `.app` with no `panel.m` / `settings.m` diagnostics (the `capture.m` availability warnings are
  P2.6's pre-existing weak-SCK design, D26). The AX code compiles and links.
- **`assumption` → V6.10.** P5.2 is code, not a heard result. A human runs VoiceOver (or Accessibility
  Inspector) against `gotab -switch` and `gotab -settings` and confirms each tile is announced with
  title + app, the selection is spoken on every ⌥⇥ cycle, and every settings control has a spoken
  label. An agent host has no screen reader — the same wall P3.1's screenshot and V6.1's keypress
  hit. The integrator adds V6.10 and tags P5.2 `assumption` in `docs/ROADMAP.md`.
