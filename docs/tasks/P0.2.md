# P0.2 — CGEventTap hotkey from Go

**Branch:** feat/P0.2   **Phase:** 0   **Depends on:** none   **Blocks:** P2.3, and the summon path

## Goal

Capture ⌥⇥ from a Go process and find out how late the keystroke arrives. This is the last Phase 0
unknown. The budget is **< 5 ms** for the callback, because a keystroke that feels dropped is the one
thing a switcher cannot do.

## Files you may touch

- `spike/hotkey/` (new)
- `docs/DECISIONS.md` (append)
- `docs/ROADMAP.md` (box + log)

## What has to be answered

1. Can a `CGEventTap` be installed and driven from Go, and does it see ⌥⇥ before the frontmost app does?
2. **How late is the event when we see it?** `CGEventGetTimestamp` is the moment the event entered the
   system, so event → callback is measurable directly rather than inferred.
3. **What does the C → Go crossing cost on a tap callback thread?** D1 measured 39 ns for a callback on a
   thread the Go runtime already owns. A tap callback arrives on a CoreFoundation thread the runtime has
   never seen, and attaching one is not free. Measure the first crossing separately from the rest.
4. Can the event be swallowed, so ⌥⇥ does not also reach the app underneath?

## Running V6.1 when a human is at the machine

```bash
go run ./spike/hotkey -manual -n 20
```

Grant Accessibility to the **terminal**, not to the binary — see the note below. The first press is
discarded (one-off costs the user never feels twice). ⌥⇥ is swallowed while the spike runs, so nothing
underneath will see it.

## Notes

**TCC judges the responsible process** (ALTTAB-LESSONS §5): run from a terminal and the grant that
matters is the *terminal's* Accessibility permission, not this binary's. `AXIsProcessTrusted` must be
checked and reported plainly — an ungranted tap is created successfully and then simply never fires,
which looks identical to "the hotkey does not work".

**A tap is disabled by the system if its callback is too slow** (`kCGEventTapDisabledByTimeout`). The
callback must handle that event type and re-enable itself, or the hotkey dies silently after one stall.
This is not defensive noise; it is the documented failure mode.
