# P2.3a — Accessibility enumeration: the real switchable set

**Branch:** main (Phase 2 is serial)   **Phase:** 2   **Depends on:** P2.2

## Goal

Enumerate the windows a user can actually switch to, via `kAXWindowsAttribute` per running application,
in one cgo crossing. D19 showed `CGWindowList` over-reports by ~8x and that its titles disappear without
Screen Recording, so this — not P2.2 — is the list the switcher is built on.

**P2.3 is split.** This is the enumeration half. The observer half (P2.3b: `AXObserver` registration,
callbacks that enqueue and return) needs somewhere to enqueue *to*, and `internal/app` does not exist
yet. Splitting follows P0.4's precedent rather than blocking on the event loop.

## Files you may touch

- `internal/platform/darwin/` (shim.h, shim.m, window.go)
- `cmd/gotab/main.go` — `-list` should show the real set; the raw CG list stays reachable for comparison
- `docs/ROADMAP.md`, `docs/DECISIONS.md`

## What has to be answered

1. **How does an `AXUIElement` become a `core.WindowID`?** The model is keyed by `CGWindowID` (P1.0) and
   AX does not hand one out through public API.
2. **What does AX cost?** Every attribute read is Mach IPC to another process. D1's 31 ns cgo figure is
   irrelevant next to it; the question is whether enumeration stays inside D5's launch-time budget.
3. **What happens when an application does not answer?** A wedged app must not wedge the switcher.
4. **How much does AX actually remove**, measured against D19's 59-of-7?

## Acceptance

- [x] one crossing enumerates every application's windows; crossings do not grow with N
- [x] windows come back with a `CGWindowID` that matches P2.2's — 5 of 5 on the measured run, which
      is the evidence that the private `_AXUIElementGetWindow` returns real numbers
- [x] `FlagMinimized` and `FlagHidden` are set from AX, not guessed
- [x] an unresponsive application cannot block enumeration — 0.25 s messaging timeout per app
      element, and a timeout skips that app rather than failing the run. **Not exercised against a
      genuinely wedged app**; that is V6.5's.
- [x] `./scripts/check.sh` green, purity gate included

Per D16 this task writes no tests.

## Notes

`AXIsProcessTrusted` gates all of it. Without the grant every call returns `kAXErrorAPIDisabled` and the
list comes back empty — which must be distinguishable from "no windows", the same distinction P2.2 had
to make for titles.

## What this task found, and did not close

D20: AX is the right filter and the wrong list. It missed a second Chrome window and an `.Accessory`
app's titled window, and **both AX calls succeeded** — this is not an error path. The join that fixes it
is P2.3c. Question 2 of "what has to be answered" — what AX costs — is deliberately unanswered: D16 defers
measurement, and V6.3 owns it.
