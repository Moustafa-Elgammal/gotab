# P1.2 — MRU ordering kernel

**Branch:** feat/P1.2   **Phase:** 1   **Depends on:** P1.0

## Goal
`Order` produces the list the user sees: most-recently-focused first.

- `internal/core/order_test.go`


## Behaviour that is not obvious
- **Only two things may reorder** (ALTTAB-LESSONS §3): an attention decision (`Promote`) and a
  structural repair (`Rebuild`, after a window appears or vanishes). Nothing else. If you find
  yourself reordering on a title change, that is the bug this rule exists to prevent.
- `Rebuild` sorts by `Focus` descending and **must be stable** for equal `Focus` — windows never
  focused all share `Focus == 0`, and an unstable sort makes them shuffle between summons.
- `Rebuild` reuses `o.Rows[:0]`; it must not allocate once warm.
- `Promote` moves a row to the front, shifting the rest down. It does not touch the `Model`.
