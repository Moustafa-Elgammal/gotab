# P5.1 — Localization scaffold (proof: the permissions dialog)

**Branch:** feat/P5.1   **Phase:** 5   **Depends on:** the carve (internal/i18n frozen, build.sh
ships `resources/*.lproj/`, `cmd/gotab` routes the permissions CLI strings through `i18n.T`)

## Goal

The localization mechanism is real and proven end to end on one subsystem — the permissions
onboarding dialog. When this is done, `internal/i18n` resolves keys from the embedded English and
from a `<locale>.lproj/gotab.json` override in the bundle; `internal/platform/darwin/permissions.m`
draws its NSAlert through `NSLocalizedString`; and a German locale (`de`) is a complete overlay for
every permissions string, shipped in the bundle, as the proof that override-loading works on both
runtimes. Nothing else is localized this round — that is deliberate (see Not in scope).

  them with the current literals; refine only if the wording is genuinely better, and keep the key
  names).
- `internal/platform/darwin/permissions.m` — replace the four hard-coded `@"…"` strings and the two

- `resources/de.lproj/Localizable.strings` — new. German for every `perm.alert.*` key.
- `resources/de.lproj/gotab.json` — new. German for every `perm.cli.*` **and** `perm.alert.*` and
  `update.*` key present in `internal/i18n/en.json` (the Go side reads this file).

Nothing else. Do **not** touch `internal/i18n/*.go`, `cmd/gotab/`, `scripts/build.sh`, `settings.m`,

need, stop and escalate.

## Contract

- `permissions.m`'s NSAlert renders `messageText`, both bullet lines, the instructions paragraph, and
  the "Open System Settings" / "Quit" button titles via `NSLocalizedString`. Key names exactly as in
  `internal/i18n/en.json` (`perm.alert.title`, `perm.alert.needAccessibility`,
  `perm.alert.needScreenRecording`, `perm.alert.instructions`, `perm.alert.openSettings`,
  `perm.alert.quit`).
- `resources/en.lproj/Localizable.strings` and `resources/de.lproj/Localizable.strings` are valid
  `.strings` (`plutil -lint` clean) with matching key sets — every `perm.alert.*` key, no extras.
- `resources/de.lproj/gotab.json` is valid JSON, a flat `string → string` map, covering every key in
  `internal/i18n/en.json`.
- `\n` handling: the carve's `en.json` values for `perm.alert.needAccessibility` /
  `needScreenRecording` / `instructions` carry leading/trailing newlines that `permissions.m` used to
  hard-code. Keep the same whitespace in the `.strings` values so the alert layout is unchanged.

## Notes

No tests (D23). The `.strings`/`.json` split is per-package doc in `internal/i18n/doc.go` and D40:
one `.lproj` directory per locale, `Localizable.strings` for AppKit, `gotab.json` for Go, kept in
step by hand. `permissions.m` is compiled without ARC — `NSLocalizedString` returns an autoreleased
`NSString`, which is fine inside the existing `@autoreleasepool`.

## Findings

- **`permissions.m`.** The six user-facing strings (`messageText`, the two bullet lines, the
  instructions paragraph, both button titles) now come from `NSLocalizedString(@"perm.alert.*", nil)`
  with keys identical to `internal/i18n/en.json`. No behaviour change: the values in
  `en.lproj/Localizable.strings` are byte-for-byte the old literals, newlines included, so the alert
  lays out as before. The only other literals in the file — the `x-apple.systempreferences:` URL
  schemes in `pane_url` — are not user-facing and stay as-is.
- **The two runtimes resolve independently.** Outside a bundle (`go build`, `go test`, `go run`)
  `NSLocalizedString` returns the key, which is harmless here because the modal is only ever shown
  from inside `GoTab.app`, where AppKit reads `Contents/Resources/<lang>.lproj/Localizable.strings`;
  the headless path prints the Go `perm.cli.*` strings instead. The Go side never reads a `.strings`
  file — `i18n.Load` reads `<lang>.lproj/gotab.json`. Hence `de.lproj` ships both files and they are
  kept in step by hand (D40).
- **`de` is a loader exercise, not a translation.** German covers every key so both loaders are
  proven end to end, but it is not a supported build (per "Not in scope"). The `%s`/`%v` verbs in the
  `update.*` values are kept in the same order — Go's `fmt.Sprintf` is positional and the callers in
  the frozen `cmd/gotab` pass args in a fixed order.
- **Scratch check (not committed, per D23).** A throwaway `package main` importing `internal/i18n`:
  with the default locale `i18n.T("perm.cli.waitingAccessibility")` returned the English
  (`"gotab: waiting for Accessibility …"`); after `i18n.SetLocale("de")` + `i18n.Load("resources")`
  it returned the German (`"gotab: warte auf Bedienungshilfen …"`); `perm.alert.title` resolved to
  German through the same catalog; switching back to `en` restored English. Deleted before commit.
- **Not migrated, deliberately.** `cmd/gotab` usage text (integrator-frozen; the `perm.cli.*` subset
  it needs was seeded in the carve), `settings.m` and `panel.m` (P5.2's files this round), and
  macOS system-locale detection (needs CFLocale/cgo, which `internal/i18n` avoids by design — D40).
  No `internal/i18n/*.go` file was touched; the frozen `T` / `SetLocale` / `Load` API was sufficient.
- **`scripts/build.sh`** already had the `resources/*.lproj` copy step and the `CFBundleLocalizations`
  / `CFBundleAllowMixedLocalizations` plist keys from the carve, so shipping the two `.lproj` dirs
  needed no build-script change — only the resource files themselves.
