# P7.2 — Dead windows leave the list

**Phase:** 7  **Depends on:** P2.7 (the event loop / `doRescan`), P2.3c (the join), D46 (the gap)
**Owns:** `internal/app/loop.go`, `internal/platform/darwin/process.go` (new)

## Goal

V6.5 (D46) found the switcher offering tiles it could not action. P7.1 makes an un-resolvable-but-live
window still useful by activating its application. P7.2 is the other half: a window that is genuinely
gone must leave the model, so P7.1 never has to fall back for a window that should not be on screen at
all.

Two ways a window dies, and `doRescan`'s prune now covers both:

1. **Ordinary close (⌘W), app still running.** The window disappears from *both* `kAXWindowsAttribute`
   and `CGWindowList`, so `Enumerate` does not return it, so it is absent from `l.scratch` and its
   `present` entry stalls at the previous generation. The existing not-seen prune removes it. The
   roadmap said "it already is — confirm the removal path fires": it is, and it does. No code needed
   for this case beyond a comment naming it.
2. **The owning process exited, but a stale CoreGraphics entry still names the window (D46).** A
   `cg`-only window the join recovered can outlive its app by a rescan or two — CoreGraphics has not
   caught up, so `Enumerate` still returns it and the not-seen check cannot fire. A pid-liveness
   check in the prune catches it.

## Contract

```go
// internal/platform/darwin
func ProcessAlive(pid int) bool   // syscall.Kill(pid, 0): nil|EPERM ⇒ alive, ESRCH ⇒ gone
```

- `doRescan`'s single backwards prune loop keeps its swap-with-last invariant (i decreases by 1,
  Len() by ≤ 1 per iteration, so `i < Len()` holds) and now removes a window on **either** ground:
  not seen this generation, **or** `!ProcessAlive(model.Apps[i])`. At most one `Remove` per iteration
  (branch 1 `continue`s), so the invariant is unchanged.
- **One `syscall.Kill` per distinct pid per pass.** A dead app's N windows share a pid; `l.pidAlive`
  (a `map[core.AppID]bool` on `Loop`, `clear`ed — never reallocated — each pass, sized in `New` like
  `present`/`allowed`) memoizes the result within the pass. No per-pass allocation added.
- Pure Go, no cgo: `syscall.Kill` is POSIX, not CoreGraphics, so it needs no crossing and does not
  belong behind the shim. It lives in `internal/platform/darwin` and not `internal/app` because the
  event loop should not grow platform syscalls, and not `internal/core` because that package is pure.
- MRU order is untouched: removal is a structural repair (PLATFORM-LESSONS §3), which the prune was
  already allowed to do; `RebuildFrom` after it sorts by `FocusSeq`, which a prune does not change.

Notes taken while writing it:

- **The ⌘W case was already covered** by the not-seen prune (loop.go's backwards loop): confirmed by
  reading `Enumerate` in `window.go` — a ⌘W'd window is in neither `FromAX` nor `FromCoreGraphics`,
  so it is never appended to `dst`, so `present[id]` never reaches the current `gen`. The added
  comment names this path so a future reader does not think the liveness check is what handles it.
- **`ProcessAlive` treats `EPERM` as alive.** A window's owning process is this user's, so `EPERM`
  should not occur — but if it ever does (a setuid helper, a sandbox quirk), keeping the window is
  the safe error: P7.1 can still reach it, and the not-seen prune will remove it once it truly goes.
- The check runs against `core.Window.App`, which `window.go` fills from `w.pid` — the CoreGraphics /
  AX owner pid, the same value P7.1's C side resolves through `pid_for_window`.
