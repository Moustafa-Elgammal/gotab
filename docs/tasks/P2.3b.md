# P2.3b — Accessibility observers

**Phase:** 2  **Depends on:** P2.3a, P2.7  **Owns:** `observe.h`, `observe.m`, `observe.go`

## Goal

Register an `AXObserver` per application so the window set is re-read when it actually changes, instead
of on the ticker `gotab -watch` currently uses as scaffolding.

## Files you may touch

- `internal/platform/darwin/observe.h`, `observe.m`, `observe.go` — **yours alone**
- `docs/tasks/P2.3b.md` (this file: tick acceptance, record findings)

**Do not touch** `shim.h`, `shim.m`, `shim.go`, `window.go`, `internal/app/`, `cmd/gotab/`,
`docs/ROADMAP.md`, `docs/DECISIONS.md`. Wiring and bookkeeping are the integrator's.

## Contract

Expose exactly this, and nothing that requires editing another file:

```go
// StartObservers watches every regular application and calls onChange when the window set may have
// changed. onChange runs on an AppKit-owned thread and must return immediately.
func StartObservers(onChange func()) error
func StopObservers()
```

## Acceptance

- [x] observers registered for `kAXWindowCreated`, `kAXUIElementDestroyed`,
      `kAXFocusedWindowChanged`, `kAXWindowMiniaturized`, `kAXWindowDeminiaturized`
      *Measured: every one of the 7 regular applications running on this machine registered all five
      (mask `0x1f`), and all five were observed being delivered from a real application.*
- [x] applications launching and quitting are picked up (`NSWorkspace` notifications), not just those
      present at start
      **Conditional, and the condition is the integrator's:** this needs a MAIN RUN LOOP in the
      process. Measured both ways — see Findings 1. `grep -rn "CFRunLoopRun\|NSApplicationMain\|\[NSApp run\]" cmd/gotab internal/app`
      currently returns nothing, so as the tree stands today this half does not fire in `gotab`.
      Nothing in the files this task owns can fix that.
- [x] the callback body does nothing but call `onChange` — no allocation, no logic, no logging
      *`observe_callback` is one line: `goObserveChange();`. Every NSWorkspace path hands off to the
      observer thread rather than crossing into Go on the thread it was posted on, so every crossing
      comes from one thread.*
- [x] observers are removed on StopObservers; no leaked `AXObserverRef` or run-loop source
      *Measured with `leaks` over 20 start/stop cycles — see Findings 4.*
- [x] `./scripts/check.sh` green

## Notes

`ARCHITECTURE.md#the-cgo-rule`: callbacks enqueue and return. `onChange` will be `Loop.Rescan`, which is
a depth-1 latch and never blocks (D22) — you do not need to coalesce, but you must not block.
The observer's run-loop source must be added to a run loop that is actually running, or nothing fires.

## Findings

**1. `NSWorkspace` launch/terminate needs a running main run loop. Nothing else here does.**
Measured on this machine with a throwaway `package main` in two configurations, identical otherwise:

| | app launched after start | its new windows | its quit |
|---|---|---|---|
| main thread running `CFRunLoopRun` | delivered, on the main thread | seen | seen |
| no main run loop anywhere | **never delivered** | **never seen** | **never seen** |

Not late, not on another thread — never. `queue:nil` instead of `[NSOperationQueue mainQueue]` changes
nothing; the block still runs on the main thread, because it is the *posting* that needs the loop, not
the hop. The AX observers themselves are unaffected: with no main run loop they still fire normally for
every application that existed at start, because they are scheduled on a run loop this file owns and
runs. So the failure is partial and silent, and the symptom would be "gotab sees the apps that were
open when it started, and no others". Stated as a precondition in `observe.h` and in the `StartObservers`
doc comment. `cmd/gotab` does not run one yet.

**2. A freshly launched application registers only *some* of the five, and the two it drops are the two
that matter.** Measured against TextEdit, one dispatch after its launch notification:

```
pid=11877 AXWindowCreated        err=0
pid=11877 AXUIElementDestroyed   err=-25204   (kAXErrorCannotComplete)
pid=11877 AXFocusedWindowChanged err=-25204
pid=11877 AXWindowMiniaturized   err=0
pid=11877 AXWindowDeminiaturized err=0
```

A retry gated on "did anything register" would have seen 3 of 5, called it a success and left that
application permanently half-observed — no window-close and no focus events from it for as long as it
ran. The gate is therefore "all five": a per-pid bitmask, retried on `{0, 250, 500, 1000, 2000, 4000}`
ms, asking only for what is still missing and reusing the observer already installed. Confirmed working:
`add_app pid=14443 mask=0x18 fresh=1` followed by `add_app pid=14443 mask=0x1f fresh=0`.

**3. `kAXUIElementDestroyed` on the *application* element does report descendant windows.** This was
the open question — registering it on the app element could plausibly have notified only about the app
element's own destruction, which would have meant tracking every window element individually. It does
not: closing one document window of TextEdit while the app stayed alive delivered
`kAXUIElementDestroyed` for it. It is also the noisiest of the five (13 in a row from one app during a
deminiaturize), which is precisely what D22's depth-1 latch is for.

**4. Leak measurement, and one leak that was in the first draft.** `leaks` against a process that ran 20
`StartObservers`/`StopObservers` cycles:

| | leaks | bytes |
|---|---|---|
| run loop retained forever ("bounded, deliberate") | 351 | 83,312 |
| run loop released after readers drain | **1** | **32** |

Zero `AXObserverRef` and zero `CFRunLoopSource` in both — the observer teardown was right from the
start. The 351 were 20 × `ROOT LEAK <CFRunLoop>` (3072 bytes each) plus their mode sets: the immortal
`CFRetain` on the observer thread's run loop, which is one per process only if you start once. It is now
released in `gt_observers_stop`, after `g_posting` (the count of threads inside
`run_on_observer_thread`) drains to zero, so no thread can be between the load of `g_loop` and the call
on it. The remaining single 32-byte leak is a system `xpc_date_t`, not ours.

**5. Background applications generate a steady trickle of `kAXFocusedWindowChanged` with nobody
touching the machine.** Docker Desktop and Finder each posted them in pairs every couple of seconds on
an idle system. `onChange` is therefore not rare, and the integrator should not treat a signal as
evidence that anything changed — which is what D22 already assumes.

**6. `NSWorkspace` reports every helper process, so terminate had to be filtered.** Every `osascript`
invocation is a launch and a terminate as far as `NSWorkspace` is concerned; firing `onChange` on all of
them cost two spurious rescans per shell command in testing, and a rescan is an AX round trip per
application. Terminate now fires only when the pid was actually being observed *or* the application's
policy read `.Regular` (read on the notification thread, while the `NSRunningApplication` is still
fresh). Launch was already filtered to `.Regular`. Idle callbacks with only shell churn happening:
2 per phase before, 0 after.

**7. Not verified.** Behaviour under a revoked-mid-run Accessibility grant. `gt_observers_start` checks
`AXIsProcessTrusted()` and returns `GT_ERR_NOT_TRUSTED`, but nothing here re-checks afterwards, and what
macOS does to live `AXObserverRef`s on revocation was not tested — it needs a human toggling System
Settings during a run.
