# V6.11 — `gotab -check-update` against the live feed

**Branch:** verify/check-update-live   **Phase:** 6   **Depends on:** P5.3 (`internal/update`),
V6.12 (the pipeline that populates the host).

## Goal

P5.3 (D39/D41) built `internal/update.Check` and verified it only against a local
`python3 -m http.server` copy of the manifest. V6.12 then stood up the real host —
`https://moustafa-elgammal.github.io/gotab/latest.json`, rendered and published by
`release.yml` on every `v*` tag. This task runs `gotab -check-update` against **that** URL and
confirms the three outcomes the acceptance names.

## Acceptance — all met, 2026-09-08

Run from a build stamped with `-ldflags "-X main.version=…"` so `runCheckUpdate` does not
short-circuit on `"dev"`. The live feed advertised `0.2.1` at the time of the run.

- [x] **Newer available.** `go run -ldflags "-X main.version=0.1.0" ./cmd/gotab -check-update`:

  ```
  gotab: 0.2.1 is available (you have 0.1.0) — https://github.com/Moustafa-Elgammal/gotab/releases/tag/v0.2.1
    Adds the app icon to the bundle (plus a release-pipeline notes fix)
  ```

  Exit 0. The URL is the release tag page and the second line is the manifest `notes`.

- [x] **Up to date.** Same command with `-X main.version=99.0.0`:

  ```
  gotab 99.0.0: up to date.
  ```

  Exit 0.

- [x] **Unreachable host.** Same command with `-X main.version=0.1.0` and `HTTPS_PROXY=http://127.0.0.1:1`
      (nothing listening):

  ```
  gotab: update check failed: update: fetch https://moustafa-elgammal.github.io/gotab/latest.json: Get "…": proxyconnect tcp: dial tcp 127.0.0.1:1: connect: connection refused
  ```

  One line on stderr, **exit 0** — a check that cannot reach the feed is "not now", never a failure.

- [x] The `github.io` URL `301`-redirects to the account's custom Pages domain
      (`elgx.me/gotab/latest.json`); Go's HTTP client follows it transparently, which is why
      `FeedURL` stays on `github.io` (D42 / V6.12).

- [x] Committed regression coverage for the same paths without a network: `internal/update/check_test.go`
      (added under V6.6) drives `check` over `httptest` for available / up-to-date / non-200 /
      malformed / oversized / unreachable.

## Notes

- `main.version` is `"dev"` for any `go run` / bare `go build`; `-check-update` prints the
  "development build — skipping" line and makes no request. Only a release-stamped binary (the CI
  build, or an explicit `-ldflags -X`) exercises the network path — that is by design (D39).
- Nothing in the product changed for this task. It is a verification run plus the note that the
  earlier `assumption` ("only run against a local manifest, `FeedURL` has no host") is discharged.
- `min_macos` in the served manifest is still decoded-not-enforced (P5.3 scope); a build that needs a
  newer OS than the host can still be offered. Unchanged, and out of scope here.
