# P2.4 — Spaces: which Space is a window on, and which is current

**Phase:** 2  **Depends on:** P2.2  **Owns:** `space.h`, `space.m`, `space.go`

## Goal

Fill in `core.SpaceID`, which nothing populates today. D20 measured Accessibility failing to report a
second Chrome window and guessed "it is on another Space" without confirming it. **This is the task that
turns that guess into a number.**

## Contract


## Findings (measured 2026-09-07, live desktop, both TCC grants held)

Five runs of a throwaway harness over a live session. Window counts drift between runs because the
desktop is in use; every conclusion below held on every run.

### The machine has exactly one Space

    Spaces()                              = [1]   (count 1)
    CurrentSpace()                        = 1     (stable across 5 consecutive calls, every run)
    CGSGetActiveSpace                     = 1
    CGSManagedDisplayGetCurrentSpace      = 1     (menubar display 37D8832A-…)

Raw `CGSCopyManagedDisplaySpaces`: one display, one Space, `id64 = 1`, `ManagedSpaceID = 1`,
`type = 0`. All five SkyLight symbols resolved via `dlopen`/`dlsym`; none was missing.

**This is the single most important number here, and it constrains everything below.**

### The D20 question, answered

D20 guessed that the Chrome window Accessibility failed to report "must be on another Space". On this
session:

| | count |
|---|---|
| CoreGraphics layer-0 candidates | 54–63 |
| Accessibility switchable set | 5–7 |
| windows with a Space the WindowServer would name | 7–9 |
| windows reported unknown (0) | 46–54 |
| **windows on a Space other than the current one** | **0, every run** |

Representative run — the AX-invisible windows, with their Space:

    wid   space  ax   policy  app             title
    69    1      NO   0       Google Chrome   (untitled)
    38    1      NO   0       Claude          Claude
    67    1      yes  0       Google Chrome   DATASHARD LONDON: Overview | LinkedIn
    39    1      yes  0       Google Chrome   Read, Listen & Study the Noble Quran

**Both windows Accessibility could not see were on Space 1 — the current Space.** Both belong to
processes with activation policy 0 (a regular application), so this is not D20's Notion Calendar
`.Accessory` case; window 69 is D20's Chrome case exactly, an extra Chrome window that
`kAXWindowsAttribute` did not return.

**So the guess in D20 does not hold as a general rule.** A window can be invisible to Accessibility
while sitting on the Space the user is looking at. On a machine with one Space it cannot be anywhere
else, and the AX misses happened anyway.

**What is still open, and it needs a human.** Because there is only one Space, this session cannot
test the converse — that a window genuinely on a *second* Space reports a SpaceID different from
`CurrentSpace()`. Creating a Space needs Mission Control and a person in front of it. **The negative
above is established; the positive is not.** V6.2 already has a human in front of multiple Spaces and
is where the other half belongs.

### 0 means unknown, and it is not a silent default

The risk `core.SpaceID` exists to guard against is inventing a Space. Tested directly by asking for
window ids that cannot exist, in the same call as real ones:

    SpacesOf([999999 999998 1 2]) -> [0 0 0 0]

Real windows in the same session returned 1. `CGSCopySpacesForWindows` declines rather than falling
back to the current Space, so a 0 out of `SpacesOf` means the WindowServer would not place the
window — not that the query failed to try.

### One crossing, and why C loops inside it

`CGSCopySpacesForWindows` returns the deduplicated *set* of Spaces for a batch, so it cannot be
aligned to its input. Measured directly, passing every id in one call:

    54 ids -> 1-element array [1]
    62 ids -> 1-element array [1]
    63 ids -> 1-element array [1]

The loop is therefore forced, and it runs on the C side of exactly **one** cgo crossing —
`len(spaces) == len(ids)` held on every run. Cost over 54–63 windows: **1.4–4.8 ms total, 22–87 µs
per window.** The spread is WindowServer IPC and is real; budget the top of it.

### A lead, not followed (recorded per the D21 convention)

`CGSCopyWindowsWithOptionsAndTags` inverts the question — given a Space, which windows are on it —
costing one round trip per *Space* (1–5) instead of per *window* (54–63). It works: options 0,
tag-mode 0 returned 18–19 windows for Space 1.

It is not used, because cross-checking it against `SpacesOf` on one run showed the two agreeing on
every window **except exactly the two Accessibility also could not see** — `SpacesOf` placed windows
69 and 38 on Space 1; the inverted call omitted both. The bogus-id probe rules out `SpacesOf`
guessing, so this is a difference of meaning: "which Space is this window assigned to" versus "which
windows are currently ordered in on this Space". P2.4 was asked the former. Switching would need a
multi-Space machine to validate, which this one is not.

### Integrator notes

- **No build change is needed.** SkyLight is resolved with `dlopen`/`dlsym` at runtime, so there is no
  `-F` framework path and no `CGO_LDFLAGS_ALLOW`; `scripts/build.sh` is untouched. A missing symbol
  degrades one feature to "unknown" instead of failing the launch.
- Nothing calls `CurrentSpace`/`SpacesOf`/`Spaces` yet. Wiring `core.Rules.CurrentSpace` and
  `Model.Spaces` is integration work, not this task's.
- `Rules.CurrentSpace = 0` must keep meaning "do not filter by Space" — with 46–54 of 63 windows
  reporting 0, a Space filter that treats unknown as off-Space would empty the switcher.

## Notes

`SpaceID` 0 means **unknown** and must stay distinguishable from a real Space — `internal/core/api.go`
is explicit that SkyLight is private and may decline to answer. Never invent a Space.

SkyLight is a private framework (`/System/Library/PrivateFrameworks/SkyLight.framework`). Candidates:
`CGSCopyManagedDisplaySpaces`, `CGSGetActiveSpace`, `CGSCopySpacesForWindows`. Linking a private
framework may need `-F` in `CGO_LDFLAGS` and `CGO_LDFLAGS_ALLOW`; `dlopen`/`dlsym` is the fallback and
is more honest about the API being private. **If it cannot be done reliably, say so** — an accurate
negative is a successful task here (see AGENTS.md, "Scope discipline").
